# JACO-PIM — מסמך ארכיטקטורה ותכנון

> מסמך זה הוא העוגן לתכנון המערכת: החזון, המודולים, מודל הנתונים, הארכיטקטורה
> הטכנית, האינטגרציות ומפת הדרכים. מתעדכן ככל שהתכנון מתפתח.

---

## 1. חזון ומיקום

**JACO-PIM** היא מערכת לניהול מידע על מוצרים (Product Information Management),
לשימוש **פנימי** בעיקר. היא משמשת כ**מקור האמת לתוכן המוצרים** — שם שיווקי,
תיאור, מאפיינים, תמונות וסיווג.

**התובנה המרכזית:** היום אין חיבור בין אתר המכירה (WordPress) למערכת הקופה
(קומקס). JACO-PIM הופכת ל**גשר** שמחבר ביניהן — מושכת נתונים מסחריים מקומקס,
מעשירה אותם בתוכן איכותי, ומזינה את האתר וקטלוגים ללקוחות.

**שפה:** עברית בלבד (אין רב-לשוניות).

- **WooCommerce** → חלון ראווה בלבד; מקבל תוכן מ-PIM ונתונים מסחריים (דרך PIM).

## 3. המודולים

### ליבה (Core)
| מודול | תיאור |
|------|-------|
| מוצרים (Products) | הרשומה המרכזית: מק"ט, שם, תיאור, סטטוס |
| מאפיינים דינמיים (Attributes) | שדות גמישים לכל סוג מוצר — הלב של PIM |
| קטגוריות (Categories) | עץ סיווג היררכי |
| וריאנטים (Variants) | וריאציות מוצר (מידה/צבע) |
| מדיה (Media/DAM) | תמונות וקבצים (Supabase Storage) |

### איכות ותהליך (Quality & Process)
| מודול | תיאור |
|------|-------|
| שלמות נתונים (Completeness) | אחוז מילוי המוצר; אילו שדות חובה חסרים |
| תהליך ואישור (Workflow) | טיוטה → בבדיקה → פורסם → ארכיון |
| היסטוריה (Audit Log) | מי שינה מה ומתי |

### נתונים פנימה/החוצה (Data I/O)
| מודול | תיאור |
|------|-------|
| ייבוא מקומקס | משיכת מק"ט/מחיר/מלאי |
| סנכרון ל-WooCommerce | דחיפת תוכן מוצרים לאתר |
| ייצוא קטלוגים | קטלוג שיווקי (תמונות+תיאור+מחיר) ללקוח ספציפי |
| ייבוא/ייצוא קבצים | טעינה וייצוא מ-Excel/CSV |
| עוזר WhatsApp חכם (AI) | צ'אטבוט ללקוחות מעל הקטלוג — חיפוש, המלצה, מבצעים (סעיף 8) |

### פלטפורמה (Platform)
| מודול | תיאור |
|------|-------|
| חיפוש וסינון | מציאת מוצרים לפי טקסט/מאפיין/קטגוריה/סטטוס |
| הגדרות (Settings) | ניהול הגדרות מאפיינים, קטגוריות, ערוצים |
| משתמשים והרשאות | התחברות ותפקידים — **עתידי** |

## 4. מודל הנתונים והקשרים

**קיים כבר (מיגרציה 0001):** `products`, `categories`, `product_categories`,
`attribute_groups`, `attribute_definitions`, `attribute_values`, `variants`,
`media_assets`, `product_media`.

```
Product (מוצר) ─ הרשומה המרכזית
   ├── Categories       (רבים-לרבים)
   ├── AttributeValues  (אחד-לרבים) → AttributeDefinition → AttributeGroup
   ├── Variants         (אחד-לרבים)
   ├── Media            (רבים-לרבים)
   ├── ExternalRefs     (אחד-לרבים)  — קישור לקומקס / WooCommerce        [מתוכנן]
   └── RelatedProducts  (רבים-לרבים) — מוצרים קשורים                      [עתידי]
```

**תוספות מתוכננות (מיגרציות עתידיות) לתמיכה באינטגרציות:**
| תוספת | מטרה |
|------|------|
| שדות מסחריים על `products` | `price`, `stock`, `barcode` (מגיעים מקומקס) |
| `external_references` | מיפוי מוצר ↔ SKU בקומקס / product_id ב-Woo + סטטוס סנכרון + זמן |
| `customers` | לקוחות, לצורך קטלוגים מותאמים |
| `catalog_templates` / `catalog_items` | הגדרת קטלוג שיווקי ללקוח (אילו מוצרים, אילו מחירים) |
| `sync_log` | תיעוד מה נשלח/התקבל ומתי |

## 5. ארכיטקטורה טכנית (שכבות)

```
┌─ הצגה (Presentation) ─ Next.js 16 App Router, תיקיית (dashboard)
│     Server Components (קריאה)  +  Client Components (טפסים)
│     רכיבי UI: shadcn/ui (RTL)
│
├─ לוגיקה (Application) ─ Server Actions  →  Services (lib/services)
│     אימות קלט: Zod (lib/schemas) — סכמה אחת לטופס ולשרת
│
├─ אינטגרציות (Integrations) ─ lib/integrations/*
│     comax (ייבוא) · woocommerce (ייצוא) · catalog (ייצוא PDF)
│
├─ נתונים (Data) ─ Supabase (lib/supabase)
│     Postgres (טבלאות)  +  Storage (מדיה)
│
└─ רוחבי (Cross-cutting) ─ Cache/Revalidate · Audit · Auth [עתידי]
```

**כלל הזהב:** ה-UI אף פעם לא ניגש ל-DB או ל-API חיצוני ישירות — תמיד דרך
שכבת `Services` / `Integrations`. הלוגיקה במקום אחד, וקל להחליף/לבדוק.

## 6. אינטגרציות — פירוט

| מחבר | כיוון | טכנולוגיה | מה עובר |
|------|-------|-----------|---------|
| **קומקס** | פנימה | API של קומקס | מק"ט, ברקוד, מחיר, מלאי |
| **WooCommerce** | החוצה | WooCommerce REST API | שם, תיאור, מאפיינים, תמונות, קטגוריות, מחיר |
| **קטלוג ללקוח** | החוצה | ייצור PDF | קטלוג שיווקי מסונן: תמונות + תיאור + מחיר ללקוח |

**הערות תכנון:**
- סנכרון מתבצע דרך פעולה יזומה ("סנכרן עכשיו") ו/או תזמון (cron).
- כל סנכרון נרשם ב-`sync_log` עם תוצאה (הצלחה/שגיאה).
- ה-`external_references` מונע כפילויות ומאפשר עדכון במקום יצירה מחדש.

## 7. מפת דרכים (סדר בנייה)

| שלב | מה בונים | ערך |
|-----|----------|-----|
| **1** | CRUD מלא למוצרים (יצירה/עריכה/מחיקה) | המסך המרכזי עובד |
| **2** | מאפיינים דינמיים (הגדרה + מילוי במוצר) | הלב של ה-PIM |
| **3** | קטגוריות + שיוך מוצרים | ארגון הקטלוג |
| **4** | מדיה — העלאת תמונות | מוצר מלא ויזואלית |
| **5** | חיפוש, סינון, שלמות נתונים | ניהול קטלוג בקנה מידה |
| **6** | אינטגרציות: ייבוא קומקס → סנכרון Woo → ייצוא קטלוגים | חיבור לעולם החיצון |
| **7** | עוזר WhatsApp חכם (AI) מעל הקטלוג | ערוץ מכירה ושירות חכם |

> שלב 7 מסתמך על תוכן עשיר (שלבים 1–4) ועל נתוני מחיר/מבצעים מקומקס (שלב 6) —
> צ'אטבוט מעל קטלוג ריק לא שימושי. לכן הוא בא אחרי הליבה והאינטגרציות.

## 8. עוזר WhatsApp חכם (AI)

צ'אטבוט שלקוחות מדברים איתו ב-WhatsApp בשפה טבעית (עברית), מעל קטלוג ה-PIM.
דוגמאות לשאלות: *"איזה סוגי בקבוקים יש?"*, *"המלץ לי על מתנה למורה"*, *"מה במבצע?"*.

### זרימה
```
לקוח ב-WhatsApp
   │ הודעה נכנסת (webhook)
   ▼
WhatsApp Cloud API (Meta)
   │
   ▼
Next.js Route Handler  (app/api/whatsapp/route.ts)
   │
   ▼
Claude (Anthropic SDK) + Tool Use ── "המוח"
   │   קורא לכלים ששואלים את ה-PIM:
   ├─ search_products(query, filters)   → חיפוש לפי סוג/קטגוריה/מאפיין
   ├─ recommend_products(לְמי/תקציב)     → המלצה ("מתנה למורה")
   ├─ get_promotions()                  → מוצרים במבצע ("מה במבצע")
   └─ get_product_details(id)           → פרטים מלאים + מחיר + תמונה
   │
   ▼
תשובה חוזרת ללקוח דרך WhatsApp Cloud API
```

### רכיבים
| רכיב | בחירה |
|------|-------|
| ערוץ | **WhatsApp Business Cloud API** (Meta) — webhook נכנס, Graph API יוצא |
| המוח | **Claude** (`@anthropic-ai/sdk`) עם **tool use** (לולאת agent) |
| כלים | שכבת שירות שמתחברת ל-PIM (חיפוש, המלצה, מבצעים, פרטים) |
| מודל | ברירת מחדל **`claude-opus-4-8`**; לבוט עתיר-תנועה אפשר לשקול `claude-haiku-4-5` / `claude-sonnet-4-6` לחיסכון |
| חיפוש סמנטי | **Supabase pgvector** — embeddings על תוכן המוצרים (לשלב מתקדם; מתחילים בחיפוש מובנה) |
| היסטוריית שיחה | טבלה לפי מספר טלפון, לשיחה רב-תורית |
| חיסכון | **Prompt caching** על system prompt + הגדרות הכלים (קבועים) |

### עקרונות תכנון
- ה-AI לא ניגש ל-DB ישירות — הכלים עוברים דרך שכבת ה-`services`, בדיוק כמו ה-UI.
- מתחילים מ**חיפוש מובנה** (קטגוריה/מאפיין/מחיר); מוסיפים **חיפוש סמנטי** (pgvector + embeddings) כשנרצה המלצות "רכות" יותר.
- כל הודעה נכנסת מאומתת (חתימת webhook) לפני עיבוד.

## 9. החלטות והנחות יסוד

- **עברית בלבד** — אין רב-לשוניות; מפשט את המודל.
- **קומקס = מקור האמת** למחיר ומלאי; **PIM = מקור האמת** לתוכן.
- **אין היום סנכרון** בין האתר לקופה — PIM ייצור את החיבור הזה.
- **קטלוגים ללקוחות** = קטלוג שיווקי (תמונות + תיאור + מחיר), לא רק מחירון.
- **משתמשים והרשאות** — נדחו לשלב מאוחר; הארכיטקטורה ערוכה להוסיף בהמשך.
- **עוזר WhatsApp** — מבוסס Claude (`claude-opus-4-8` כברירת מחדל) עם tool use;
  מתחיל בחיפוש מובנה ומוסיף חיפוש סמנטי (pgvector) בהמשך. דורש חשבון
  WhatsApp Business + מפתח Anthropic API (החלטות פתוחות: מודל מדויק וספק
  embeddings — Voyage/Cohen למולטי-לשוני — יוכרעו בשלב 7).
- **שרת פיתוח** — `npm run dev` משתמש ב-webpack (Turbopack קורס על חלק
  ממערכות Windows). `npm run dev:turbo` לניסיון Turbopack.
